## Key Decisions Made
- Tech stack: Next.js + MySQL, hosted entirely on client's existing Hostinger Business plan (Node.js supported — confirmed).
- Payment gateways: Stripe + PayPal + Klarna (all three).
- VAT: must be admin-configurable, not hardcoded (client currently at 19% but wants flexibility).
- Checkout: guest checkout + optional account creation, both supported.
- Shipping: free above €30, flat rate below.
- Legal scope: Privacy Policy (GDPR), Impressum, Widerrufsrecht, GPSR — dev builds pages/workflow, client owns final legal text accuracy.
- Source code handover: included unconditionally in the agreement.
- Admin: single user only, no roles/permissions system needed.
- Invoices & credit notes: auto-generated, downloadable PDFs.

## Recent Work (2026-08-15 → 2026-10-07)
- ✅ **`removeChild` crash when clicking „Anmelden“ FIXED (2026-10-07):** on the logged-out `/account` page, clicking the „Anmelden“ CTA threw `Runtime NotFoundError: Failed to execute 'removeChild' on 'Node': The node to be removed is not a child of this node.` instead of opening `/login`. **Root cause was not in our code:** third parties rewrite the DOM inside React's tree — the reporter's Chrome has „German → English“ auto-translate on (`translate_allowlists: {"de":"en"}` in their profile, `accept_languages: en-US,en,ur` against our `lang="de"`), plus 12 extensions (several with `<all_urls>` + `scripting`). Chrome translation rewrites text nodes into `<font>` wrappers, so React's deletion phase calls `parent.removeChild(node)` on a node that was moved/detached and the whole commit throws — the dev overlay replaces the navigation. Reproduced deterministically in headless Chrome by re-parenting `main > div` before clicking the CTA (identical stack: `commitDeletionEffectsOnFiber` → `removeChild`), and reproduced React hydration-mismatch errors with Chrome's real auto-translate. **Fix:** new client component `src/components/shared/DomResilience.tsx`, rendered first in `app/layout.tsx` — it patches `Node.prototype.removeChild` / `insertBefore` once to degrade gracefully (remove from wherever the node actually lives, no-op if already detached, append when the insert anchor moved). It only ever fires where React would otherwise crash; normal DOM behaviour is unchanged. Verified: the same mutation now lands on `/login` with the form rendered and zero exceptions, 4 navigation cycles with real Chrome auto-translate stay clean; `tsc --noEmit` ✓, `npm run test` 45 passed. **For future reports:** a `removeChild` crash is usually the visitor's browser rewriting our DOM — check their Chrome profile's `translate_allowlists` / extensions before hunting for a component bug.
